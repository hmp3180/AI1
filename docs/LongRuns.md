### ⚠️⚠️ **팔이 여럿인 스크립트의 감시는 「첫 팔」이 아니라 「감싸는 것」에 건다**(실측 `Projects/SLM` · 2026-09-22)

긴 판은 보통 **한 `.cmd` 안에 팔을 여럿** 넣어 차례로 돌린다. 그것을 떼어 낸 뒤 감시(watch)를
**`schtasks` 가 띄운 첫 팔의 앱 pid** 에 걸었다. 그랬더니:

```
① 첫 팔이 끝난다 → 감시가 「끝났다」를 쏜다 → wakeOnce 라 감시가 소진된다
② 남은 두 팔은 한 시간 가까이 **아무도 안 보는 채로** 돈다
③ 게다가 알림 꼬리에 **첫 팔의 판정 보드**가 붙어 있어서 「셋 다 끝났다」로 읽었다
```

⚠️ 사람이 *"지금 감시 안 붙어 있는데"* 라고 짚어 줘서 알았다. 안 짚었으면 남은 팔이
**도중에 멎어도 영영 안 왔을** 것이다(그 경우 종료 신호 자체가 없다).

⇒ ★ **처방**: 감시는 **팔들을 감싸는 `cmd.exe` 의 pid** 에 건다. 그것이 스크립트의 수명이다.

```powershell
# 띄운 뒤 감싸는 쪽을 집는다 — ⚠️ 이름이 아니라 CommandLine 으로 (위 ③ 의 그 규율)
$c = Get-CimInstance Win32_Process -Filter "Name='cmd.exe'" |
     Where-Object { $_.CommandLine -like '*<그 스크립트>.cmd*' }
$b = @{ name=$env:CC_CHAT_NAME; pid=$c.ProcessId; label='<ASCII 로>'
        log="$sp\<첫 팔 로그>.txt"; wake=@('FATAL','assert','Exception') } | ConvertTo-Json
```

⇒ 🧾 ★★★★ ***첫 팔의 종료는 일의 끝이 아니라 일의 1/n 인데, 알림은 똑같이 「끝났다」로 온다*** —
그래서 **가장 속기 쉬운 모양**이다. 알림을 받으면 **무엇이 끝났는지부터** 확인해라(파일 목록의
mtime 한 줄이면 된다).
⇒ ⚠️ 그리고 **알림 꼬리를 판정 근거로 쓰지 마라** — 꼬리는 「마지막으로 찍힌 것」이지
「이 일의 결과」가 아니다(🧾 *표제 줄을 찾는 검색은 표제 줄만 준다* 의 알림 판).

### ⚠️⚠️⚠️ **긴 계산 앱이 「조용히·확률적으로」 죽을 때 — 진단 순서**(실측 `Projects/ML` · 2026-08-24)

★ **결론부터: 범인은 우리 코드가 아니었다.** 열네 판을 「힙 손상」으로 쫓았는데
**다른 워크트리가 같은 이름의 앱을 돌리고 있었다.** 아래 순서로 보면 **첫 두 걸음에서** 끝난다.

#### ① `stderr` 는 답이 아니다 — **디버거를 붙여라**

⚠️⚠️ **`stderr` 가 비어 있다는 것은 「아무 말도 없었다」가 아니다.** 프로세스에 붙은 남의 코드는
**`OutputDebugString`** 으로 말하고 그것은 **디버거만** 받는다 ⇒ 리다이렉트로는 **원리적으로
안 보인다.** 실측: 그 줄들이 OBS 훅의 것이었고 **열네 판 동안 한 번도 안 보였다.**

```powershell
# MinGW 툴체인에 gdb 가 있다. batch 로 한 줄이면 된다.
gdb -batch -x cmds.gdb --args <앱>.exe <인자들>
#   cmds.gdb :  handle SIGSEGV stop print / run / bt / thread apply all bt / info registers
```

⛔⛔ **`gdb -batch -p <pid>` 로 「살아 있는 앱」에 붙지 마라 — 그것이 앱을 죽인다.**
실측(2026-09-05): 명령 파일에 **`detach` 를 적었는데도** batch 종료와 함께 대상 프로세스가
사라졌다(종료 코드 255). ⇒ ⚠️ **여섯 시간짜리 실행을 그 한 줄로 끝냈다.**
⇒ ★ 위 `--args` 형태(**gdb 가 직접 띄운다**)는 안전하다 — 죽어도 되는 실행이기 때문이다.
⇒ ★ 살아 있는 것을 들여다볼 때는 **죽지 않는 도구부터**: 메모리·핸들·스레드 상태(`Get-Process`) ·
  **CPU 코어 수** · **GPU 점유율**(`Get-Counter '\GPU Engine(*)\Utilization Percentage'`).
  ⭐ 실측에서 그 셋만으로 원인이 잡혔다(*"CPU 0.42코어 + GPU 11.8% ⇒ 둘 다 한가하다 = 대기"*).
⚠️⚠️ 그리고 그 사건의 **원인 자체가 이것이었다** — **다른 워크트리의 앱이 gdb 아래 멈춘 채
같은 GPU 의 큐를 잡고 있었고**, 우리 앱의 fence 가 영영 오지 않았다(같은 판이 **3240배**).
⇒ ★ **긴 실행 전에 같은 GPU 를 쓰는 프로세스를 본다**(위 GPU 카운터 한 줄).

#### ② **종료 코드를 읽어라 — 그것이 서명이다**

| 종료 코드 | 뜻 |
|---|---|
| **`0xFFFFFFFF`(−1)** + 모든 스레드 −1 + **gdb 무신호**(`No stack`) + **WER 이벤트 0건** | ⚠️ **예외가 아니다.** `TerminateProcess(h, −1)` 이고 그것이 곧 **`.NET` 의 `Process.Kill()`** = PowerShell **`Stop-Process -Force`** 다 ⇒ **누가 밖에서 죽였다** |
| `0xC0000005` (WER `Application Error` 1000) | 진짜 접근위반 |
| `0xC0000409` | fail-fast(스택/힙 손상 검출) |

★ **그래서 「조용한 죽음」의 첫 물음은 「누가 죽였나」다** — 「무엇이 깨졌나」가 아니다.

#### ③ ⚠️⚠️⚠️ **이름은 프로세스를 고유하게 가리키지 않는다**

이 저장소는 워크트리가 여럿이고(`G:\My\PE_GIT` · `G:\My\PE_GIT_2` …) **같은 이름의 앱**이 동시에
돈다. 그래서 **이름을 쓰는 모든 것이 남의 프로세스를 집는다**:
- `Stop-Process -Name <앱>` — **금지**(이미 위에 적혀 있다). `Process.Kill()` 이라 종료 코드 −1 이다.
- **`Get-Process -Name <앱>` 유령 검사** — 남의 것을 「유령」으로 오판한다.
- **이벤트 로그 필터 `Message -like '*<앱>*'`** — ⚠️ **두 워크트리를 가릴 수 없다.**
  실측으로 이것에 속았다: 「`0xc0000005` in `ucrtbase.dll` ⇒ 힙 손상」이 **남의 프로세스**
  얘기였을 수 있고, 그 오진으로 **여섯 번의 긴 실행을 버렸다.**

⇒ ★ **진단도 처방도 하나다: `CommandLine` 을 같이 읽어라.**
```powershell
Get-CimInstance Win32_Process -Filter "Name='<앱>.exe'" |
    ForEach-Object { "pid=$($_.ProcessId) parent=$($_.ParentProcessId) $($_.CommandLine)" }
```
⇒ ★ **그리고 재는 동안에는 이름을 고유하게 만들어라** — exe 를 복사해 `<앱>_<트리>.exe` 로
돌리면 이름으로 죽는 사고가 **원리적으로** 불가능하다(바이트가 같으니 측정은 안 바뀐다).
⇒ ⚠️⚠️ **그 처방에는 대가가 있다 — 빌드가 그 복사본을 갱신하지 않는다**(실측 2026-09-07 ·
  `Projects/ML`). exe 를 `<앱>_<트리>.exe` 로 복사해 두고 그 사이에 `build.bat` 을 돌리면
  **복사본은 옛 바이너리로 남는다** ⇒ ⛔ **조용히 옛 코드를 돌린다**(실측: 복사본 12:48 ↔ 빌드 13:49
  ⇒ 23분짜리 판이 「직전 회차의 반복」이 됐다).
  ⇒ ★ **처방 둘**: ㈀ **재실행마다 다시 복사한다**(`Copy-Item -Force` 한 줄) ·
  ㈁ ⭐ **앱이 「이 판이 무엇을 보나」를 배너로 찍게 한다** — 실측에서 그 배너의 한 줄이
  **45초 만에** 옛 바이너리를 잡았다(그 줄이 없으면 23분을 버린다).
  ⚠️ 그리고 **mtime 을 견주는 것이 진단**이다: `Get-Item <앱>.exe, <앱>_<트리>.exe | Select LastWriteTime`.
  ⇒ ⛔⛔⛔ **㈂ 다 쓰면 지워라 — `run.bat` 이 그 복사본을 집는다**(실측 2026-09-11 · `Projects/MLW`).
  그 스크립트는 `for %%F in (*.exe) do set "EXE=%%F"` 라서 🧾 ***마지막 것이 남는다***(덮어쓴다)
  ⇒ 알파벳 순으로 `<앱>.exe` → `<앱>_<트리>.exe` 이므로 **복사본이 이긴다.**
  ⚠️⚠️ 증상이 원인과 안 닮는다: **사람이 새 플래그를 줬는데 아무 일도 안 났다**(모르는 플래그는
  조용히 무시되므로 **평소 화면이 그냥 뜬다**) ⇒ 「그 기능이 안 된다」로 읽힌다.
  ⇒ ★ 진단 한 줄: `ls bin_dev/*.exe` — 🧾 ***exe 가 둘이면 그것이 먼저 의심할 것이다.***
⇒ ✅✅✅ **실측 판정**: 이름을 고유하게 하니 **60/60 완주 × 3연속**(그 직전 세 판은 같은 이름으로
씨앗 **5 · 17 · 20** 에서 죽었다). 기저 완주율 **26%** ⇒ H0 에서 `0.26³ = **1.8%**`.
⚠️ 「누가 죽였나」를 목격하진 못했다(종료 감사 로그가 꺼져 있다) — 증거는 **종료 코드 서명 ·
예외 없음 · 이름 충돌의 실재 · 이름 바꾸면 3/3 완주** 넷이 한 방향인 것이다.

#### ⚠️⚠️ **표집으로 구간을 나눠 잴 때 — 마지막 구간은 자기 값을 말하지 않는다**

표집의 **끝점 몇 개**가 그 구간 밖의 일(종료·마감)을 담는다. 실측 **두 번 거의 같은 크기**로
밟았다(+11.5MB · +11.3MB) 그리고 한 번은 **그것으로 표제 결론을 틀리게 적었다.**
⇒ ★ 처방 둘: ㉠ **꼬리 몇 점을 뺀 기울기를 나란히 찍는다**(갈리면 그것이 신호다)
㉡ 끝에 **아무것도 안 하는 꼬리 구간**을 둬서 **어떤 실측 구간도 마지막이 아니게** 만든다.
⚠️⚠️ 그리고 **꼬리 구간은 「시간」으로 잡아라** — 「아무것도 안 한다」를 반복 수로 두면
순식간에 끝나 **표집 점이 한 개**가 되고 마감 점프를 못 흡수한다(실측). ★ **누수 0 으로
확인된 일**을 돌리면 시간이 들면서 자기 기대값이 0 이라 오염을 곧바로 드러낸다.
⚠️ 그리고 **반복당 값을 손으로 나누지 마라** — 여러 판에서 조금씩 틀렸다. 프로그램이 접게 한다.

#### ④ **프로세스의 성장**을 봐라 — 기계의 가용 메모리가 아니다

⚠️ *"16GB 가 남았으니 메모리 부족이 아니다"* 는 **기계 상태**다. 실측으로 그 옆에서
**프로세스가 0.71 MB/초로 완벽한 직선으로** 자라고 있었다(완주에 1.2GB) — **열네 판 동안 못 봤다.**
```powershell
$ap = Get-Process -Id $childPid
"{0:N1}MB priv / {1} handles / {2} threads" -f ($ap.PrivateMemorySize64/1MB), $ap.HandleCount, $ap.Threads.Count
```
★ **핸들·스레드를 같이 찍어라** — 셋 중 무엇이 자라는지가 곧 결함의 종류다(메모리만 자라면 누수).

#### ⑤ 이 툴체인에서 **못 쓰는 도구**(먼저 확인하라 — 처방 전에)

| 도구 | 이 저장소에서 | 확인 한 줄 |
|---|---|---|
| **ASan** `-fsanitize=address` | ⛔ **불가** — MinGW-w64 는 **libasan 을 안 싣는다**(플러그인 헤더만 있다) | `g++ -fsanitize=address x.cpp` → `cannot find -lasan` |
| UBSan | ⛔ 런타임 없음 | `ls <툴체인>/lib/lib*san*` |
| **gflags / PageHeap** | ⛔ 도구 없음 + **IFEO 레지스트리라 관리자 권한** 필요 | `Get-Command gflags` · `IsInRole(Administrator)` |
| **gdb** | ✅ **있다**(MinGW 17.1) ⇒ **남은 강한 도구는 이것** | `gdb --version` |

★ **도구를 처방하기 전에 가용성을 확인한다** — *"다음 도구는 ASan 이다"* 라고 적어 뒀는데
그 도구가 **이 툴체인에 없었다.** 한 줄이면 알 수 있었다.

★ clean 을 하려면 지우는 것: `<Proj>/.build/win64/` 와 `<Proj>/.build/last_build_state_*.json`.
⚠️ 그리고 **「clean 이 고친다」는 최종 반증됐다**(clean 완주 3·죽음 1 ↔ 증분 완주 2·죽음 7).
